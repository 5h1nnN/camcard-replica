# 30 张合成名片 OCR 基准测试

测试时间：2026-11-03

设备：iPhone 17 Pro 模拟器，iOS 26.4（仅使用这一台模拟器）

测试集：`TestData/BusinessCardDataset` v1.0.0

最终流水线：候选名片边界筛选 → 透视校正 → 原图与校正图并行 Vision OCR（`zh-Hans`、`en-US`）→ 结构化完整度评分择优 → `BusinessCardFieldParser`

| 指标 | 初始实现 | 优化后 | 变化 |
|---|---:|---:|---:|
| 完成处理 | 30 / 30 | 30 / 30 | — |
| 流水线异常 | 0 | 0 | — |
| 非空 OCR | 27 / 30（90.0%） | 30 / 30（100%） | +10.0 pp |
| OCR Ground Truth 值召回 | 187 / 224（83.5%） | 224 / 224（100%） | +16.5 pp |
| 非空字段解析准确率 | 140 / 224（62.5%） | 224 / 224（100%） | +37.5 pp |
| 全字段准确率（含空字段） | 186 / 270（68.9%） | 270 / 270（100%） | +31.1 pp |
| 缺失字段保持为空 | 46 / 46（100%） | 46 / 46（100%） | 0 pp |
| 总耗时 | 29.151 秒 | 63.589 秒 | +34.438 秒 |
| 平均耗时 | 0.972 秒/张 | 2.120 秒/张 | +1.148 秒/张 |

最终 30 张中有 11 张采用透视校正图的 OCR，19 张回退或保留原图 OCR。双路径选择消除了错误裁边导致的整卡或半卡文字丢失，但代价是在检测到候选边界时需要额外执行一次 OCR，因此总耗时约为初始实现的 2.18 倍。

“OCR Ground Truth 值召回”表示 Ground Truth 中的非空字段值是否出现在最终选中的 OCR 原文中；“非空字段解析准确率”表示解析后的结构化值与 Ground Truth 经大小写、空白、标点等格式归一化后是否一致。

## 实现改进

- 不再无条件信任检测到的矩形；边界候选会按面积、长宽比和检测置信度排序，避免把分栏或内部色块当成整张名片。
- 检测到可校正边界时，同时识别原图和校正图，再按结构化字段、联系方式、文本行数和字符数评分，选择信息更完整的一份。
- 地址标签、双语电话标签会在入库前清理；补充了中英文公司和职位关键词。
- “工作室”“实验室”不再因末尾“室”被误判为地址；职位或公司中的 `Mobile` 不再被误判为电话标签。
- 支持 OCR 将中英文姓名分成相邻两行的情况，并修复中文姓氏“陆”会被 Swift `Character.isNumber` 视作数字而遭排除的问题。

## 自动化入口

测试实现位于 `CamCardReplicaTests/BusinessCardDatasetTests.swift`。测试集只复制到单元测试 Bundle，不进入 App 安装包。每次运行会在 xcresult 中附加完整 JSON 报告，并逐张记录原图 OCR、校正图 OCR、最终选择来源和字段对比。

```bash
xcodebuild \
  -project CamCardReplica.xcodeproj \
  -scheme CamCardReplica \
  -destination 'platform=iOS Simulator,OS=26.4,name=iPhone 17 Pro' \
  -parallel-testing-enabled NO \
  -only-testing:CamCardReplicaTests/BusinessCardDatasetTests/testThirtyCardDatasetOCRBenchmark \
  test
```

本基准只把“30 张全部完成且无流水线异常”作为 XCTest 的硬性通过条件，准确率通过 JSON 报告比较。当前 100% 结果仅代表这套固定的合成测试集，不能等同于真实世界泛化准确率；后续应继续加入不同字体、低照度、反光、复杂真实背景和更多语言的独立留出样本。
